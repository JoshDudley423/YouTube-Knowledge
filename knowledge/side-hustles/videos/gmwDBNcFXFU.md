# Make Money With This New AI Agent That Works 24/7
Channel: The Koerner Office | https://www.youtube.com/watch?v=gmwDBNcFXFU | Published: 2026-09-04

Chris Koerner solo screen-recorded demo (Part 1 of 2): testing "Grok Bot" (an agentic AI tool built on Grok) to see if it can build a sellable software product from a single prompt, with no coding knowledge required. Part 2 (selling the product) is referenced as forthcoming but not covered in this transcript.

## The business idea
Use an agentic AI coding tool (Grok Bot, comparable to having ChatGPT/Claude actually execute build-test-fix work rather than just answering questions) to build a real, sellable SaaS product from a single well-crafted prompt — positioned as a repeatable path to creating software products without hiring a developer or learning to code yourself. The specific product built in this episode ("Morning Lock," Chris's working name) is a **productivity/distraction-blocking app**: a Mac menu bar app + Chrome extension that locks access to Gmail/Mail (and optionally any other website/app) outside of a defined daily time window, with a password-protected override that Chris configured to require his spouse's involvement to unlock — a forced "time-boxing" mechanism for people (like him) who don't follow self-imposed calendar blocks.

## Process / steps described
1. **Origin of the idea**: personal pain point — Chris struggles to stay accountable to self-imposed calendar time-blocking, but has more discipline when money/external accountability is involved. Decided to lock himself out of email/distracting sites for all but a defined daily window (5:00-10:00 AM) to force inbox-zero discipline, rather than block work apps during work hours.
2. **Tool used**: Grok Bot, an agentic AI assistant capable of taking actions (not just generating text) — connecting to and operating other services (Replit, GitHub, Stripe) on the user's behalf.
3. **Setup approach**: deliberately did NOT connect Grok Bot to unnecessary accounts/services upfront — cites advice from a "Grok Bot expert" friend (Billy) to treat the agent "like an employee": give it one focused job/scope rather than a scattered list of asks, to get better results.
4. **Prompt engineering step**: rather than writing the technical prompt himself, Chris first described the plain-language idea to Claude and asked Claude to translate it into a detailed, technically precise prompt using correct engineering terminology, since he doesn't know the technical vocabulary himself. Claude's response flagged an important technical constraint before he proceeded: a website/Replit-hosted web app cannot force-quit a native Mail app — the real build needed to be a native Mac menu-bar app plus a browser extension, not a pure web app. Claude also flagged that an AI agent cannot create an Apple Developer account or Chrome Web Store developer account on the user's behalf — those still require ~20 minutes of manual human setup.
5. **Execution**: pasted the Claude-generated prompt into Grok Bot, authorized Stripe (in test mode) for eventual payment processing, and authorized GitHub/Replit connections. Also pre-approved Grok Bot to accept Replit hosting overage charges autonomously up to a cap of $100/day, to avoid needing to manually approve incremental costs.
6. **Result**: Grok Bot autonomously built, tested (Chris observed it running "23 different tests," all passing), and fixed the Mac menu-bar app and Chrome extension — described as a fully autonomous "build → test → fix" loop, repeated until working — with the full working product completed in **31 minutes and 37 seconds** from a single initial prompt.
7. **Iteration after the initial build**: Chris made a few additional small feature requests directly in follow-up prompts (e.g., "list out all the most commonly used apps and websites on this computer/browser so the user can easily choose which ones to block" — implemented immediately; a broken icon — fixed immediately). No UI/branding direction was given at any point (colors, layout, etc.) — Grok Bot made all visual design decisions independently.
8. **Resulting product features**: time-windowed lock/unlock schedule (configurable per day, e.g., unlocked Friday until 10 PM on demand), an auto-populated list of the user's most-visited sites/apps (pulled directly from the Mac, allowing one-click selection of which to block), a password-based unlock mechanism designed to be held by someone other than the user (e.g., a spouse) to enforce real accountability.
9. **Stated next step (Part 2, not covered here)**: Chris intends to actually sell access to this app as a SaaS product using Stripe, once the working prototype (already validated for his own personal use) is finished.

## Numbers / concrete details
- Full working build time: ~31.5 minutes from a single detailed prompt to a fully functional, tested Mac app + Chrome extension.
- Pre-authorized autonomous spending cap given to the AI agent for hosting overages: up to $100/day without requiring manual approval.
- No revenue, pricing, or customer numbers are given in this episode — this is a pure product-build demonstration, not a monetization case study (that is explicitly deferred to a "Part 2" not included in this transcript).

## Tools/platforms named
Grok Bot (agentic AI builder tool, the episode's main subject), Claude (used to translate the plain-language idea into a precise technical prompt for Grok Bot), Replit (hosting/backend where the app was actually built), GitHub (code storage, connected automatically by Grok Bot), Stripe (payment processing, connected in test mode for the eventual paid product), Chrome Web Store / Apple Developer account (manual human setup steps an AI agent cannot complete itself).

## Caveats / risks
- Explicitly framed as a live, unscripted experiment/proof-of-concept ("I've never touched Grok Bot in my life") rather than a tested repeatable business — no monetization, customer acquisition, or retention data exists yet at the time of this recording.
- A meaningful technical limitation is surfaced mid-build: purely AI-agent-buildable web apps cannot perform certain native OS-level actions (e.g., forcibly locking a native Mail app) — some products genuinely require a native app/browser-extension architecture that the AI cannot fully assemble without a couple of manual human steps (developer account setups).
