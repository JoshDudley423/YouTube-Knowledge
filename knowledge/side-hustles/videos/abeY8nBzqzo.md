# The Most Copy-Pastable Online Business (Thanks to AI)
Channel: The Koerner Office | https://www.youtube.com/watch?v=abeY8nBzqzo | Published: 2025-09-22

Guest: Omar Choudhry, builds AI-generated "directory" websites (programmatic SEO content sites) using vibe-coding tools, creator of 5 Day Sprint (a framework/course for launching these projects).

Business idea: build large-scale "directory" websites — sites with thousands of programmatically generated pages (think TripAdvisor/Yelp-style structure: category > city > listing) — using AI to both generate the site's code (via "vibe coding" tools like Cursor and Claude Code) and generate the actual page content, then monetize via organic Google/LLM search traffic (SEO), affiliate links, lead capture, or a small paid tier — with near-zero paid advertising spend.

Key case studies and numbers:
- GuiltyChef.com: an AI-content recipe directory (restaurant-inspired recipes, e.g., "Wingstop Korean Q wings recipe"). Ranks #1 organically in Google for many restaurant-recipe keywords, above Pinterest, Instagram, Reddit, and video results; also cited as a top source when asked directly inside ChatGPT (LLM answer engines are pulling from the same well-structured content). Traffic history: built mid-2024, no growth signal from Google between roughly March-August 2024 despite continuously adding pages, then took off starting August/September 2024 and has grown "up and only to the right" since — now getting almost 11,000 organic visits/month from just 160 total pages, at essentially zero ad spend. Revenue: modest, roughly $700-800/month from a small paid tier (users pay to generate their own AI recipes), largely passive since the site isn't actively promoted.
- BestDubai.com: a Dubai tourism/restaurant/hotel directory site, content aggregated from Google reviews via AI (ratings, amenities, check-in times, FAQs, maps). Built after noticing Dubai's official tourism directory was thin/bloggy. Domain cost $900 (found available by chance — a similarly structured domain for a different country, "BestSaudi.com," was priced around $100,000, which the guest treated as a strong signal of the underlying keyword's commercial value). Already ranks #2 in Google (behind only TripAdvisor) for specific restaurant review searches, above Facebook, Zomato, Reddit, OpenTable.
- Live-demo build during the episode: a "high protein snacks" directory page built with a single ~2-sentence prompt, using a pre-built "5 Day Sprint" project framework/scaffold — the AI autonomously added features never explicitly requested (a full comparison chart, a "protein per dollar" filter/calculator, a lead capture form, an interactive macro calculator) purely from being instructed to "be the best SEO" page possible.
- Claimed a directory/duplicate site (same features/functionality, different niche/branding) can be spun up from an existing one via "duplicate project" (right-click, rename) in under 15-20 seconds once the underlying framework/codebase exists — the remaining work is swapping content, branding, and images for the new niche.
- Separately, describes running an agency doing custom AI-driven development work for clients, citing projects billed at $100,000 completed in about 5 days using this same Cursor/Claude Code skill set.

Step-by-step method described for launching a directory from scratch:
1. Keyword/niche research using Ahrefs (free account sufficient) — search broad seed terms, then look for long-tail keyword variants with a "keyword difficulty" (KD) between 0 and 30 and the highest possible monthly search volume (example cited: "high protein snacks" showing KD 9 with 81,000 monthly searches — called a rare, extremely attractive combination; typically even 1,000 monthly searches is considered good).
2. Domain research: try to secure the closest possible exact-match .com domain to your primary keyword using a tool like InstantDomainSearch.com (shows all available TLD variants for a search term at once, green = available). The guest argues an exact-match domain isn't strictly required for ranking (GuiltyChef.com ranks #1 despite an unrelated domain name) but gives "an added advantage" when available.
3. Content/technical SEO structure: use schema.org markup (structured metadata Google looks for — e.g., opening hours, price range, payment methods for a restaurant listing) — the more relevant schema properties present, the higher the likelihood of ranking. Historically this required an SEO strategist plus a content team plus designers/developers (a team of 4-5 people); now a single prompt to Cursor/Claude Code ("create me a category for restaurants, make it schema-compatible, include all relevant properties") generates this instantly, and doing this at scale (hundreds/thousands of pages) is what builds a full programmatic directory.
4. AI-generated content ranks fine in both Google and LLM answer engines (ChatGPT/Claude) — explicitly pushes back on the idea that AI content can't rank or that special files like llm.txt are required; his sites have neither and still rank #1 in both.
5. Tooling stack: sites built visually in Webflow, with AI-driven functional/interactive components layered on via Cursor and Claude Code (guest states he does not use Replit or Lovable, finding Cursor/Claude Code easier for this workflow). Uses Firecrawl (firecrawl.dev) inside Cursor to scrape/analyze a competitor site (e.g., "here's TripAdvisor.com, understand everything they do") as live market/competitor research feeding directly into a generated build prompt — described as one of the most valuable tips in the episode. Uses Supabase for the database layer (explained in beginner terms: a database is just a spreadsheet — rows, columns, and multiple tables). Uses shadcn/ui (shadcn.com) as a pre-built component library so the AI-generated UI doesn't look like generic "AI slop." Uses Dribbble's little-known, no-longer-linked-but-still-public "/buckets" page (dribbble.com/buckets) to browse other users' saved design inspiration collections for free, then can literally save an inspiration screenshot into the project's local folder and tell Claude Code to "take inspiration from this image and apply it to the products grid UI."
6. Workflow pattern: use Cursor's own chat for planning/market research (has it write the actual prompt to hand to Claude Code, since "the most valuable way to use AI is to get AI to talk to AI"), then paste that generated prompt into Claude Code (run via terminal), which acts as the execution/coding layer; iterate with small, single, compartmentalized instructions rather than large multi-part asks, since piling on multiple tasks at once causes the AI to make mistakes — "you are the master... trust your own intelligence."
7. 5 Day Sprint (the guest's own product, 5daysprint.com) provides a one-line setup string that, pasted into Cursor, auto-scaffolds an entire project (framework, UI library installation, AI-tool interoperability configuration) in minutes — described as compressing what would traditionally be "3 months of CTO-level work" into that single prompt.

Monetization/growth angles discussed: zero paid advertising across all examples (pure organic/SEO traffic); potential monetization layers mentioned include affiliate links (e.g., Amazon links on product-comparison directory pages), email capture, retargeting pixels, and even selling ad/placement space to brands bidding for prominent spots within content (e.g., a retailer paying to appear when a user clicks an ingredient link).

Caveats/pushback addressed directly:
- Addresses viewer skepticism that "AI is making directories irrelevant" — argues the opposite: directory-style content reduces friction between a question and an answer, which remains valuable regardless of the search interface (Google vs. ChatGPT), and traffic to his own sites was still growing at time of filming.
- Argues search engines (Google) are not dying despite the rise of LLM-based search — cites Google's continued massive traffic (SimilarWeb) as evidence, and the historical false alarm around Google's earlier "instant answer" snippets supposedly killing click-throughs.
- Explicitly addresses the "isn't this just an AI wrapper that will become obsolete" critique: argues (a) obsolescence risk doesn't matter because the process of building teaches transferable skills and confidence that carry into the next project, and (b) most real technology risks (e.g., the guest's own iPhone repair and parts businesses, expected to become obsolete as "unbreakable" phone glass/cases emerged) tend to persist far longer than feared — his 15-year-old original excuse for exiting that space never actually materialized as a threat.
- Notes an "always be building" mindset: encourages starting even if a given niche/site might not be a long-term moat, since repeated execution builds the skill and momentum that compounds into future, better opportunities.
